## 1. 需求

### R1（已交付）：魂符的集中收纳与批量放出 / 收回

现有 TLM 里「装有女仆的魂符」只能一键一枚地放，且放出必须点在方块上表面；
玩家带几十只女仆时，收纳、改名、单独放出都很繁琐。期望：

1. 有一个可随身携带的容器，把魂符集中放进去，容量足够（≥ 27）；
2. 一个键放出**所有己方**女仆，不限距离，只处理已加载区块；
3. 一个键收回**所有己方**、不限距离的女仆，并报告数量；
4. 放出落点不再依赖"方块上表面"，避免"无安全落点"；
5. 别人的魂符 / 女仆一律不动，且给出跳过提示；
6. 不能因为巨型 AABB 查询被 Sable/航空学这类优化模组判定为异常。

### R2（已交付）：单只女仆的选择性放出

「K 全放」粒度太粗。期望：

1. 按住一个键打开轮盘，滚轮选择某一只；
2. 每项显示姓名、好感度、生命值、状态（收纳 / 在外 / 骑乘）+ 维度；
3. 松开键执行：收纳 → 在主人位置放出；在外 → 收回；骑乘 → 拒绝并提示；
4. 服务端权威：客户端只发目标标识，服务端重新校验。

### R3（已交付）：给女仆改名，供轮盘显示

1. 女仆界面内有入口，点击后可改名，32 字上限，留空恢复默认；
2. 不消耗命名牌（轮盘功能依赖命名，消耗会阻碍使用）；
3. 保存后名字牌、界面、轮盘立即生效；
4. 关闭命名界面回到女仆界面，而不是退回世界。

### R4（已交付）：袋中扫帚与扫帚联动

1. 魂符袋可以同时放女仆扫帚，逐把占格；
2. 一个键从袋中取出扫帚放到视线指向的地面，并自动完成「放扫帚 → 放出好感度最低的女仆 → 玩家骑乘」；
3. 落点不可用时不消耗、无反应；
4. 下车后扫帚与女仆自动回到袋中（袋满才退到背包）。

### R5（未开始）：可配置化与死亡保护

1. 容量、冷却时间可配置；
2. 死亡时魂符袋不掉落（目前只保护掉落物本体：发光、无敌、无限存活、防虚空）。

## 3. 当前限制

- 容量固定 27、操作冷却固定 1 秒（R5）。
- 袋中扫帚放置要求「视线指向方块 + 原版手长内 + 落点无碰撞且无实体」。
- 界面打开期间卸下饰品，界面内改动不会写回（关闭后重开即可）。
- 未做"死亡时不掉落"的额外保护（R5）。
- 同一玩家同时只维护一条扫帚联动；服务器重启会丢失联动记录（女仆留在原地，可手动 L 收回）。
- 本机无显示器，`runClient` 无法运行；客户端界面（轮盘渲染、铅笔按钮位置）需要人工验收。

## 4. 风险与注意

| 风险 | 说明 | 应对 |
|---|---|---|
| 上游 API 变更 | TLM 的 `ItemSmartSlab` / 组件名是二进制依赖，版本升级可能改签名 | `gradle.properties` 固定 versionId；升级时先跑自测 |
| 优化模组拦截实体操作 | Sable/航空学、万法皆通等会拦截大范围查询或实体移除 | 不用巨型 AABB；收回后校验实体确实移除，被拦截则不生成魂符 |
| 大包同步 | 袋内容含几十只女仆的 NBT | persistent-only 组件，只同步数量 |
| 客户端渲染无自动化测试 | 无头环境无法验证 GUI | 依赖人工验收清单（见 M2/M3 标红项） |
