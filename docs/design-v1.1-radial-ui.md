# 命名栏 + 女仆轮盘：表现形式 / 外观 / 操作逻辑 设计草案

> **归档说明（2026-11-25）**：这是动手前的界面方案选型草案，已选定并实现（方案 A 内联名字栏 → 1.2.0 改为铅笔弹窗；三栏轮盘 → 1.1.0）。
> 保留原文作为设计留档，不再随实现更新。
>
> 范围：只描述"长什么样、怎么操作、信息怎么组织"，**不含代码实现**。
> 目的：在动手前选定一套 UI 方案。

---

## 0. 现状与设计前提

- 现有键位：`K` 放出袋中全部己方女仆、`L` 收回全部（均可配置，支持 Shift/Ctrl/Alt 组合）。
- 现有界面：魂符袋 = 原版三行箱子（27 格），无自定义控件。
- 下一版本要加的两件事：
  1. **命名**：给女仆（或魂符）起一个名字，供轮盘显示；
  2. **轮盘**：从袋里挑**指定一只**女仆单独放出（替代"K 全放"）。
- 视觉基准：TLM 本体（原版 GUI 风格 + 东方素材）与「万法皆通」的紫/墨色境界感；不引入第三方 GUI 库，尽量复用原版控件与 TLM 的 9-slice 按钮。
- 已知约束：
  - 袋内容不同步到客户端（避免传几十只女仆的整包 NBT）→ 打开轮盘时需要向服务端拉一份轻量预览数据（名字/模型/好感度/状态）。
  - 袋容量 27 格 → 轮盘/列表要处理"最多 27 项"。
  - 名字来自实体的 `CustomName`；未命名时回退到 TLM 模型名。

## 1. 命名栏（5 个方案）

所有方案共用的规则：

- 名字长度 **32 字符**（与 TLM 命名牌一致），超长截断；
- **空名字 = 清除自定义名**，轮盘回退显示模型名；
- 不允许 `§` 颜色码（与 TLM 命名牌行为一致；想要颜色以后可用"色签"扩展）；
- 与实体的"始终显示名字"（`CustomNameVisible`）联动，等价于 TLM 命名牌界面里的那个开关；
- 改名后名字牌与轮盘立即生效；
- 待定：是否像原版一样**消耗命名牌**（推荐免费，因为轮盘功能依赖命名）。

### 方案 A：女仆 GUI 内联名字栏（"点名字就地改"）

外观（176×166 的 TLM 女仆界面，标题下加一行）：

```
┌─ 女仆 ────────────────────────[×]┐
│ 名字  灵梦                      ✎ │   ← 平时是文字
│ ┌──┬──┬──┐            ┌─────────┐ │
│ │  │  │  │            │ 任务列表 │ │
│ └──┴──┴──┘            └─────────┘ │
```

点击这行（或铅笔）后，原位变成输入框，右侧出现 `✓` `✗`：

```
│ 名字  [ 灵梦___________]  ✓  ✗   │
```

- 操作：右键女仆 → 打开界面 → 点名字 → 输入 → `Enter` 确认 / `Esc` 取消；不离开界面。
- 优点：最贴合"在女仆界面加可编辑名字栏"的字面诉求；零额外窗口。
- 缺点：TLM 界面本身较满（左侧按钮列 + 中间格子 + 右侧任务列表），要挤位置；要处理"点名字行"与"点格子"的输入冲突。
- 工作量：小。

### 方案 B：铅笔按钮 + 独立命名弹窗（TLM 命名牌风格）

外观：女仆界面左侧按钮列底部（或右上角）加一个 12×12 铅笔/名字牌小图标；点开一个约 200×80 的暗色小窗：

```
┌─ 命名 ───────────────┐
│ 名字 [ 灵梦________ ] │
│ [x] 始终显示名字      │
│            [确定][取消]│
└──────────────────────┘
```

- 操作：点铅笔 → 弹窗 → 输入 → 确定；`Esc` = 取消；确认后回到女仆界面。
- 优点：不动 TLM 布局；弹窗可以**复用到袋界面和轮盘**，一次做好处处能用；风格可以照抄 TLM 自带的 `NameTagGui`。
- 缺点：多一层窗口，操作多一步。
- 工作量：小。

### 方案 C：魂符袋界面里直接改名（面向"已在袋中"的女仆）

外观：袋界面仍是原版箱子；对装着女仆的魂符 **Shift + 右键**（或选中后按 `R`），弹出与方案 B 相同的命名窗；窗内右上角带一个 32×32 的 3D 女仆头像 + 模型名，防止改错人。

```
┌─ 魂符袋 · 命名 ─────────────┐
│ 名字 [ 灵梦________ ]  [头像]│
│ [x] 始终显示名字            │
│                  [确定][取消]│
└────────────────────────────┘
```

- 操作：开袋 → Shift+右键魂符 → 输入 → 确定。
- 优点：不加按钮、就地可用；覆盖"女仆已经收进袋里"这个轮盘主场景；本质只是改 `maid_info` 里的 `CustomName`，不依赖实体在场。
- 缺点：要给原版箱子界面加输入拦截；对"已放出的活女仆"无效（那个用 A/B）。
- 工作量：小。

### 方案 D：轮盘内改名（选中项 → `R` / 右键）

外观：轮盘选中某只女仆后，圆心/下方出现提示 `[R] 重命名`；按下后轮盘收缩成方案 B 的小窗（含头像），确认后回到轮盘或直接关闭。

- 操作：按住轮盘键 → 指向目标 → 按 `R` → 输入 → 确定。
- 优点：改名与"按名字挑人"在同一个上下文；轮盘里能直接改。
- 缺点：依赖轮盘先做出来；不适合批量改名。
- 工作量：小（轮盘做出来后几乎免费）。

### 方案 E：独立"魂符名册"界面（管理向）

外观：类似 TLM 的模型选择界面：左侧 4×7 网格（每格 40×48：3D 头像 + 名字），右侧详情栏（大 3D 模型、名字输入框、模型名、好感度、锚定核心、状态），底部分页/排序/搜索。

```
┌ 魂符名册 ───────────────────────┐
│ [头][头][头][头][头][头][头]     │   ← 4×7
│ [头][头][头][头][头][头][头]     │   右侧：大头像 + 名字输入框
│ [头][头][头][头][头][头][头]     │   + 好感度 + 状态
│ [头][头][头][头][头][头][头]     │
│ [< 1/1 >]  [排序: 好感 ▾]        │
└─────────────────────────────────┘
```

- 操作：从某个入口打开（袋子右键？键位？）→ 点格子 → 右侧改名 → `Esc` 保存。
- 优点：一次解决"批量改名 / 查看 / 排序"，也是轮盘的管理层；未来可放"收回单只/查看详情"。
- 缺点：工作量最大（新界面），超出"女仆 GUI 加名字栏"的最小诉求。
- 工作量：大。

### 命名方案对比

| 方案 | 需要实体在场 | 新增界面 | 改动 TLM 界面 | 适合场景 | 工作量 |
|---|---|---|---|---|---|
| A 内联名字栏 | 是 | 否 | 是（加一行） | "在女仆界面改名" | 小 |
| B 铅笔 + 弹窗 | 是 | 小弹窗 | 加一个按钮 | 通用、可复用 | 小 |
| C 袋内 Shift+右键 | 否（袋中数据） | 小弹窗 | 否 | **轮盘主场景** | 小 |
| D 轮盘内 | 否 | 小弹窗 | 否 | 顺手改 | 小 |
| E 魂符名册 | 否 | 大界面 | 否 | 管理/批量 | 大 |

**建议**：B（或 A）+ C 的组合——两者共用同一个命名弹窗；D 等轮盘做完后顺手加；E 留到以后。

## 2. 轮盘（5 个方案）

前提：
- 交互骨架统一为"**按住键打开 → 鼠标方向/点击选择 → 松开确认**"；`Esc`/右键取消。
- 数量最多 27 只，全部方案都需处理翻页或滚动。
- 客户端只回传"槽位序号"，由服务端重新校验（防作弊、防错位）。

### 方案 1：经典扇区轮盘（8 格/页）

```
              ┌──────────┐
       ┌──────┤  灵梦 ①  ├──────┐
       │      └──────────┘      │
  ┌────┴────┐              ┌────┴────┐
  │ 魔理沙   │     ◉ 圆心    │  咲夜    │
  └────┬────┘   当前选中项    └────┬────┘
       │      ┌──────────┐      │
       └──────┤  爱丽丝 ③ ├──────┘
              └──────────┘
```

- 外观：屏幕中心半透明暗盘（半径约 110px），8 个 45° 扇区、1px 分隔线、外圈 1px 金色细边；每个扇区半径 70 处放 32×32 的 3D 女仆头像（朝向圆心，选中时放大到 36px），头像下一行 8px 名字（超长截断 + `…`）；圆心显示选中项详情：48px 大头像 + 全名 + 好感度 + 状态角标。
- 操作：按住键（约 80ms 缩放淡入）→ 鼠标方向决定高亮扇区（圆心 18px 死区防抖）→ 松开 = 放出该女仆；`Esc`/右键 = 取消；滚轮 = 翻页（圆心下方显示 `1/3`）。
- 优点：最符合"轮盘"直觉，单手快速；视觉冲击强。
- 缺点：27 只必须翻页；长名字塞不进扇区（靠圆心详情补足）。

### 方案 2：头像环 + 圆心详情卡（无扇区底色）

```
        ○ 灵梦      ○ 魔理沙
     ○ 咲夜    ┌──────────┐  ○ 爱丽丝
               │  48px 头像 │
               │  灵梦      │
               │  好感 42   │
               │  ⚓ 锚定核心 │
               └──────────┘
        ○ 露米娅    ○ 帕秋莉
```

- 外观：只有 8 个圆形头像（40px 圆框，未选中 60% 不透明，选中放大 52px + 金色描边）沿圆周排列；圆心一张详情卡（头像 56px、名字、好感度、模型名、状态）；全屏 35% 黑色遮罩 + 一圈细轨迹线。
- 操作：同方案 1；另外支持 `A/D` 或方向键旋转高亮。
- 优点：比扇区版清爽，3D 头像更突出，长名字放圆心不挤。
- 缺点：扇区感弱，拖选不如扇区直观。

### 方案 3：网格弹窗（管理型）

```
┌ 魂符袋 · 女仆选择 ─────────────────┐
│ [头+名][头+名][头+名][头+名]        │
│ [头+名][头+名][头+名][头+名]        │
│ [头+名][头+名][头+名][头+名]        │
│ [头+名][头+名][头+名][头+名]        │
│  [< 1/2 >]      [排序: 好感 ▾]     │
└────────────────────────────────────┘
```

- 外观：居中 4×7 网格（每格 40×48：头像 + 名字），箱子界面质感；标题"魂符袋 · 女仆选择"，底部翻页/排序；悬停 tooltip 显示全名、好感度、模型、状态；单击/双击放出。
- 操作：按一次键打开（不是按住），鼠标点选、滚轮翻页、`Esc` 关闭；`Shift+点击` = 收回该女仆（若在外）。
- 优点：一屏看全 27 只；支持排序/搜索；扩展性好（详情、单只收回、改名都能塞进来）。
- 缺点：不是"轮盘"；打开→点击比按住轮盘慢。

### 方案 4：径向卡片轮盘（展示型）

- 外观：选中项从圆心弹出一张 120×150 的卡片（圆角、米白宣纸质感 + 淡紫描边），卡上 64px 3D 头像、名字、好感度、模型名、锚定核心标记；其余 7 项只在环上显示 28px 小头像；背景径向渐变。
- 操作：同方案 1。
- 优点：展示感最强、信息最全，适合"晒女仆"。
- 缺点：卡片遮挡大、27 只必须翻页、视觉噪音大。

### 方案 5：极简列表 HUD（轻量）

```
                  ┌──────────────────────┐
                  │ [头] 灵梦   好感 42  │
                  │ [头] 魔理沙 好感 30  │
                  │ [头] 咲夜   好感 66  │← 高亮
                  │ [头] 爱丽丝 好感 51  │
                  └──────────────────────┘
```

- 外观：屏幕右侧竖排 8 行（20px 头像 + 名字 + 好感度），当前选中行高亮；像玩家列表。
- 操作：按住键 → 鼠标上下/滚轮选择 → 松开放出。
- 优点：实现最轻；名字再长也不怕；键盘友好。
- 缺点：不够"轮盘"，美观度一般。

### 轮盘方案对比

| 方案 | 形态 | 信息量 | 27 只处理 | 操作速度 | 视觉 | 工作量 |
|---|---|---|---|---|---|---|
| 1 扇区轮盘 | 圆盘 8 格 | 头像+名字，详情在圆心 | 滚轮翻页 | 快 | ★★★★ | 中 |
| 2 头像环 | 圆环 8 头像 | 头像，详情在圆心 | 翻页 | 快 | ★★★★ | 中 |
| 3 网格弹窗 | 4×7 网格 | 头像+名字+tooltip | 一屏 28 格 | 中 | ★★★ | 中 |
| 4 卡片轮盘 | 圆盘 + 大卡片 | 最全 | 翻页 | 中 | ★★★★★ | 大 |
| 5 列表 HUD | 竖排列表 | 名字+好感 | 滚动 | 快 | ★★ | 小 |

**建议**：第一版做 **方案 1（扇区轮盘）**；若你想"管理感"，直接做 **方案 3**，轮盘可以以后再加。

## 3. 视觉规范（方案 1/2/4 通用）

- 尺寸：圆盘外径 220px；扇区 45°；环上头像 32px（选中 36px）；圆心头像 48px。
- 配色：
  - 遮罩 `#00000059`
  - 圆盘 `#1E1B2A`（90% 不透明）
  - 分隔线 `#FFFFFF1F`，外圈 `#E8C36A66`
  - 高亮扇区 `#E8C36A33` + 1px `#E8C36A` 描边
  - 主文字 `#F2EAD3`，次要文字 `#A99F8C`
  - 好感度：`<30` 红 `#D06A6A`；`30–70` 金 `#E8C36A`；`>70` 绿 `#7FBF7F`
- 字体：原版字体；名字 8px，标题 9px；中文名字最多 6 字 + `…`。
- 动效：打开 80ms 缩放 `0.85→1`；选中扇区 60ms 放大；关闭 120ms 淡出；头像水平旋转 ±12° 跟随鼠标。
- 角标（头像右上 8×8）：⚓ 锚定核心=紫、🐴 骑乘中=蓝、已放出=绿、袋中=灰。
- 无效项（他人员魂符、空魂符）灰色 + 斜线，不可选。

## 4. 操作逻辑与边界（通用）

- **打开条件**：装备魂符袋 && 袋中至少 1 只己方女仆；否则聊天栏提示。
- **放出位置**：玩家脚前约 1.5 格、面朝方向；不可站立则落在脚下。
- **服务端权威**：客户端只发槽位序号；服务端重新校验 `Owner`、是否魂符、冷却、距离。
- **冷却/失败**：沿用现有聊天栏提示。
- **已放出的女仆**：三选一 —— (a) 不显示；(b) 显示但灰掉；(c) 显示且右键可收回。**推荐 (c)**，为后续"单只收回"铺路。
- **是否锁移动**：两套交互二选一 ——
  - **Screen 版**：打开时锁定移动/视角（原版 `Screen`），可用鼠标点击、滚轮、按钮，实现简单、扩展性强；
  - **HUD 版**：不打开 `Screen`，用 HUD 覆盖层 + 鼠标方向瞄准，松开才发请求；手感更像动作游戏，但实现复杂、与其他 HUD 模组可能冲突。
  - **建议第一版用 Screen 版**。
- **与现有键位**：`K`/`L` 保留；轮盘默认 `R`（可配置，避开 TLM 自带键）。

## 5. 组合推荐

| 组合 | 命名 | 轮盘 | 特点 |
|---|---|---|---|
| **I（推荐）** | B + C（共用弹窗） | 1 扇区轮盘 | 闭环最小，最符合"轮盘"预期 |

| IV（轻量） | D 轮盘内 | 5 列表 HUD | 最快能出 |

## 6. 需要拍板的点

1. 轮盘形态选 1/2/3/4/5 哪一个？每页 8 格还是 12 格？
2. 交互用 **Screen 版**（锁移动、能点击）还是 **HUD 版**（不锁移动）？
3. 命名入口选 A/B/C/D 哪个组合？改名是否消耗命名牌？
4. 轮盘是否显示"已放出"的女仆？右键是否作为"收回该只"？
5. 名字是否允许颜色/符号前缀（如 `♥灵梦`）？
6. 放出位置：脚前 vs 原地 vs 面前 2 格？
